# 人员与自动化工具复现导航

本文给出理解、启动和核对系统的最短路径。所有命令从仓库根目录执行。

## 1. 先确认正式架构

```text
pCPU2: StarryOS vCPU0 -> 图像预处理 -> RKNN/NPU -> 后处理/安全决策

pCPU1: StarryOS vCPU1 -> VirtIO-net/T2N1/CONTROL/STATUS/ACK
     + Zephyr vCPU0   -> 10 ms 周期任务和控制执行

NPU: 仅归 StarryOS；它不是 CPU，也不归 Zephyr
```

正式调度对比只改变 AxVisor 的 RR/FP-RR 策略。AI CPU 工作与 RTOS 共核
仅作为高竞争机制参考，不能替代正式物理拓扑。

| 阶段 | 应观察到的事实 |

| QEMU suite | 出现 `TASK123_SUITE_PASS name=<suite>`，且各场景验证器通过 |

## 7. 排查顺序

```text
入口与依赖
  -> 串口独占和波特率
  -> Reset 后是否抢到 U-Boot
  -> fastboot 设备和 RAM-only FIT stage
  -> FIT/DTB/Guest 哈希与 CPU 映射
  -> 两个 Guest 是否启动
  -> StarryOS NPU/RKNN 初始化
  -> VirtIO-net、IP、UDP 4242 和 T2N1
  -> CONTROL/ACK/STATUS 状态机
  -> 量化器、CSV/JSON 和展示页
```

不要通过放宽 watchdog、减少期望样本或删除失败记录来绕过前一层问题。
QEMU 原生 Zephyr只说明无虚拟层的等价平台基线；QEMU TCG 数值不作为
RK3588 NPU 性能。完整范围与边界见 [09-任务要求与实现覆盖.md](09-任务要求与实现覆盖.md)。
