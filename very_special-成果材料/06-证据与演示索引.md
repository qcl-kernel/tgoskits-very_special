# 证据与演示索引

具体数值和设计结论由 Task 1–3 文档负责，运行命令由
[05-复现与配置指南.md](05-复现与配置指南.md) 负责，避免在多个页面重复解释。

## 2. 一组结果如何核验

| 材料 | 核验内容 |
| --- | --- |
| 原始串口日志 | Guest 启动、周期样本、模型输出、CONTROL/ACK/STATUS、Safe/Reset |
| pcap | UDP/IP 通道、T2N1 帧、sequence/ack 和双端事务闭合 |
| 运行时配置 | vCPU/pCPU 绑定、priority、内存、MMIO、vIRQ、VirtIO 和 NPU 所有权 |
| CSV/JSON | 样本数、分位数、事务成功率、RTT、吞吐量、正确率和 recall |
| manifest 与 SHA-256 | 源码身份、运行命令、FIT/DTB/Guest/模型/图片和派生报告的一致性 |

核验顺序应从原始日志和运行配置开始，再读取 CSV/JSON 与可视化。图表和 HTML
是原始材料的派生视图，不能反向替代串口、pcap 或哈希。

## 4. 生成演示产物

```bash
scripts/competition/task123.sh board demo
TASK123_FFMPEG=/path/to/ffmpeg \
  scripts/competition/task123.sh board demo-video
```

`board demo` 不重新生成实验结果，而是严格解析已有日志，将 console 复制到
`raw/`，并生成自包含 HTML、静态 SVG/PNG 和 `artifact-index.json`。
`board demo-video` 在同一解析基础上使用可配置浏览器和 ffmpeg 录制 H.264 MP4，
随后把视频大小和 SHA-256 写回索引。浏览器、ffmpeg、帧数和帧率都可通过
`TASK123_BROWSER`、`TASK123_FFMPEG`、`TASK123_DEMO_FRAMES` 和
`TASK123_DEMO_CAPTURE_FPS` 配置。

## 5. 推荐演示顺序

1. 用架构图说明 StarryOS 两个 vCPU、Zephyr 与 NPU 的职责和物理绑定。
2. 展示 Task 1 正式实板 A/B，再用高竞争和无竞争结果说明机制边界。
3. 展示 Task 2 线格式、完整事务、独立吞吐量和一个故障恢复场景。
4. 展示 Task 3 的真实图片、跟车调整、行人急停、锁存与显式 Reset。
5. 打开原始日志、CSV/JSON、pcap 和 SHA-256，演示画面如何回溯到证据。

## 6. 解释边界

- QEMU TCG 用于功能、故障和同平台相对行为，不代表 RK3588 NPU 性能。
- 原生 Zephyr 结果来自等价 QEMU AArch64 平台，不冒充 RK3588 裸机结果。
- 固定基线与 RKNN 的准确性收益、推理成本、通信 RTT 和端到端时间分别报告。
- 演示材料只呈现已保存证据，不补造缺失事件，也不隐藏失败标志。
