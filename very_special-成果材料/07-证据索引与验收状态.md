`CONTROL -> ACK -> STATUS -> ACK` transaction/s。Task 3 的准确性收益与
推理时延分开报告，不将 QEMU TCG 数值解释为 RK3588 NPU 性能。

## 4. 已解决的资源并发问题

高内存 QEMU 场景已经通过 `TASK123_QEMU_LOCK_FILE` 和
`TASK123_QEMU_LOCK_TIMEOUT_SEC` 串行化。该设计消除了多个 `-m 8g` QEMU
同时运行、swap 压力导致串口 watchdog 误报的问题。修正后 Task 2 六场景和
Task 2+3 联合闭环均完整运行并保存双端 pcap。
